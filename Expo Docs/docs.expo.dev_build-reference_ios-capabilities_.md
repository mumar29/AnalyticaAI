# iOS capabilities
[Edit this page](https://docs.expo.dev/build-reference/ios-capabilities/<https:/github.com/expo/expo/edit/main/docs/pages/build-reference/ios-capabilities.mdx> "Edit content of this page on GitHub")
Learn about built-in iOS capabilities supported in EAS Build and how to enable or disable them.
[Edit this page](https://docs.expo.dev/build-reference/ios-capabilities/<https:/github.com/expo/expo/edit/main/docs/pages/build-reference/ios-capabilities.mdx> "Edit content of this page on GitHub")
When you make a change to your iOS entitlements, this change needs to be updated remotely on Apple's servers before making a production build. EAS Build automatically synchronizes capabilities on the Apple Developer Console with your local entitlements configuration when you run `eas build`. Capabilities are web services provided by Apple, think of them like AWS or Firebase services.
> This feature can be disabled with `EXPO_NO_CAPABILITY_SYNC=1 eas build`
## Entitlements[](https://docs.expo.dev/build-reference/ios-capabilities/<#entitlements>)
In an Expo app, the entitlements are read from the introspected app config. To edit them, see the `ios.entitlements`[](https://docs.expo.dev/build-reference/ios-capabilities/</versions/latest/config/app#entitlements>) field in your app config file. You can see your introspected config by running `npx expo config --type introspect` in your project and then look for the `ios.entitlements` object for the results.
In a bare React Native app, the entitlements are read from your ios/**/*.entitlements file.
## Enabling[](https://docs.expo.dev/build-reference/ios-capabilities/<#enabling>)
If a supported entitlement is present in the entitlements file, then running `eas build` will enable it on Apple Developer Console. If the capability is already enabled, then EAS Build will skip it.
## Disabling[](https://docs.expo.dev/build-reference/ios-capabilities/<#disabling>)
If a capability is enabled for your app remotely, but not present in the native entitlements file, then running `eas build` will automatically disable it.
## Supported capabilities[](https://docs.expo.dev/build-reference/ios-capabilities/<#supported-capabilities>)
EAS Build will only enable capabilities that it has built-in support for, any unsupported entitlements must be manually enabled via [Apple Developer Console](https://docs.expo.dev/build-reference/ios-capabilities/<https:/developer.apple.com/account/resources/identifiers/list>).

The unsupported capabilities either don't support iOS, or they don't have a corresponding entitlement value. Here is a list of all of the [official Apple capabilities](https://docs.expo.dev/build-reference/ios-capabilities/<https:/developer.apple.com/help/account/reference/supported-capabilities-ios>).
## Capability identifiers[](https://docs.expo.dev/build-reference/ios-capabilities/<#capability-identifiers>)
Merchant IDs, App Groups, and CloudKit Containers can all be automatically registered and assigned to your app. These assignments require Apple cookies authentication (running locally) as the official App Store Connect API does not support these operations.
## Debugging iOS capabilities[](https://docs.expo.dev/build-reference/ios-capabilities/<#debugging-ios-capabilities>)
You can run `EXPO_DEBUG=1 eas build` to get more detailed logs regarding the capability syncing.
If you have trouble using this feature, you can disable it with the environment variable `EXPO_NO_CAPABILITY_SYNC=1`.
To see all of the currently enabled capabilities, visit [Apple Developer Console](https://docs.expo.dev/build-reference/ios-capabilities/<https:/developer.apple.com/account/resources/identifiers/list>), and find the bundle identifier matching your app, if you click on it you should see a list of all the currently enabled capabilities.
## Manual setup[](https://docs.expo.dev/build-reference/ios-capabilities/<#manual-setup>)
There are two ways to manually enable Apple capabilities, both systems will require any existing Apple provisioning profiles to be regenerated.
### Xcode[](https://docs.expo.dev/build-reference/ios-capabilities/<#xcode>)
> Preferred method for projects that do not use [Expo Prebuild](https://docs.expo.dev/build-reference/ios-capabilities/</workflow/prebuild>) to continuously generate the native android and ios directories.
  1. Open the ios directory in Xcode with `xed ios`. If you don't have an ios directory, run `npx expo prebuild -p ios` to generate one.
  2. Then follow the steps mentioned in [Add a capability](https://docs.expo.dev/build-reference/ios-capabilities/<https:/help.apple.com/xcode/mac/current/#/dev88ff319e7>).


### Apple Developer Console[](https://docs.expo.dev/build-reference/ios-capabilities/<#apple-developer-console>)
First step is to add the respective key/value pairs to your ios/[app]/[app].entitlements (or more specific entitlements file for multi-target apps). You can refer to [Supported Capabilities](https://docs.expo.dev/build-reference/ios-capabilities/</build-reference/ios-capabilities#supported-capabilities>) to determine which entitlements keys should be added.
  1. Log into [Apple Developer Console](https://docs.expo.dev/build-reference/ios-capabilities/<https:/developer.apple.com/account/resources/identifiers/list>). Click on "Certificates, IDs & Profiles", then navigate to "Identifiers" page.
  2. Choose the bundle identifier that matches your app's bundle identifier.
  3. Scroll down and enable a capability, some capabilities may require extra setup.
  4. Scroll to the top and press "Save". You will see a dialog that says "Modify App Capabilities", press "Confirm" to continue. You will need to regenerate any provisioning profiles that use this bundle identifier before they'll be valid for building a code signed production .ipa.


If adding capabilities process has not been done correctly then your iOS native build will fail with an error similar to:
```
❌ error: Provisioning profile "*[expo] app.bacon.hello AppStore ..." doesn't support the Associated Domains capability.
❌ error: Provisioning profile "*[expo] app.bacon.hello AppStore ..." doesn't include the com.apple.developer.associated-domains entitlement.

```
