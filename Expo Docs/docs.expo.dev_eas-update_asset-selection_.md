# Asset selection and exclusion
[Edit this page](https://docs.expo.dev/eas-update/asset-selection/<https:/github.com/expo/expo/edit/main/docs/pages/eas-update/asset-selection.mdx> "Edit content of this page on GitHub")
Learn how to use the asset selection feature and verify that an update includes all required app assets.
[Edit this page](https://docs.expo.dev/eas-update/asset-selection/<https:/github.com/expo/expo/edit/main/docs/pages/eas-update/asset-selection.mdx> "Edit content of this page on GitHub")
> Available for SDK 50 and above (`expo-updates`[](https://docs.expo.dev/eas-update/asset-selection/</versions/latest/sdk/updates>) >= 0.23.0).
SDK 50 added the experimental asset selection feature, which allows the developer to specify that only certain assets should be included in updates. This can greatly reduce the number of assets that need to be uploaded to and downloaded from the updates server. This feature will work with the EAS Update server or any custom server that complies with the `expo-updates`[ protocol](https://docs.expo.dev/eas-update/asset-selection/</technical-specs/expo-updates-1>).
SDK 52 launched this feature to general availability.
## Using asset selection[](https://docs.expo.dev/eas-update/asset-selection/<#using-asset-selection>)
To use asset selection in SDK 51 and below, include the property `extra.updates.assetPatternsToBeBundled` in your app config. It should define one or more file-matching patterns (regular expressions). For example, an app.json file has the patterns defined in the following way:
app.json
Copy
```
 "expo": {
  %%placeholder-start%%... %%placeholder-end%%
  "extra": {
   "updates": {
    "assetPatternsToBeBundled": [
     "app/images/**/*.png"
    ]
   }
  }
 }

```

To use asset selection in SDK 52 and above, include the property `updates.assetPatternsToBeBundled` in your app config. It should define one or more file-matching patterns (regular expressions). For example, an app.json file has the patterns defined in the following way:
app.json
Copy
```
 "expo": {
  %%placeholder-start%%... %%placeholder-end%%
  "updates": {
   "assetPatternsToBeBundled": [
    "app/images/**/*.png"
   ]
  }
 }

```

After adding this configuration all .png files in all subdirectories of app/images will be included in updates. You have to also ensure that these assets need to be required in your JavaScript code
If `assetPatternsToBeBundled` isn't included in the app config, all assets resolved by the bundler will be included in updates (as per SDK 49 and earlier behavior).
## Verifying that an update includes all required app assets[](https://docs.expo.dev/eas-update/asset-selection/<#verifying-that-an-update-includes-all-required-app-assets>)
When using the asset selection, assets that do not match any file patterns will resolve in the Metro bundler. However, these assets will not be uploaded to the updates server. You have to be certain that assets not included in updates are built into the native build of the app.
If you are building your app locally or have access to the correct build for publishing updates (with the same [runtime version](https://docs.expo.dev/eas-update/asset-selection/</eas-update/runtime-versions>)), then use the `npx expo-updates assets:verify` command. It allows you to check whether all required assets will be included when you publish an update:
Terminal
Copy
`- ``npx expo-updates assets:verify <dir>`
> This new command is part of the `expo-updates` CLI, which also supports [EAS Update code signing](https://docs.expo.dev/eas-update/asset-selection/</eas-update/code-signing>). It is not part of the [Expo CLI](https://docs.expo.dev/eas-update/asset-selection/</more/expo-cli>) or the [EAS CLI](https://docs.expo.dev/eas-update/asset-selection/<https:/github.com/expo/eas-cli>). Only available for (`expo-updates`[](https://docs.expo.dev/eas-update/asset-selection/</versions/latest/sdk/updates>) >= 0.24.10).
You can also use the `--help` option with the command to see the available options:
Option| Description  
---|---  
`<dir>`| Directory of the Expo project. Default: Current working directory.  
`-a, --asset-map-path <path>`| Path to the assetmap.json in an export produced by the command `npx expo export --dump-assetmap` .  
`-e, --exported-manifest-path <path>`| Path to the metadata.json in an export produced by the command `npx expo export --dump-assetmap`.  
`-b, --build-manifest-path <path>`| Path to the app.manifest file created by `expo-updates` in an Expo application build (either android or ios).  
`-p, --platform <platform>`| Options: ["android", "ios"]  
`-h, --help`| Usage info.
