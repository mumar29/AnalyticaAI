# Expo Linking
[GitHub](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<https:/github.com/expo/expo/tree/sdk-50/packages/expo-linking> "View source code of expo-linking on GitHub")[npm](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<https:/www.npmjs.com/package/expo-linking> "View package in npm Registry")
An API that provides methods to create and open deep links universally.
[GitHub](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<https:/github.com/expo/expo/tree/sdk-50/packages/expo-linking> "View source code of expo-linking on GitHub")[npm](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<https:/www.npmjs.com/package/expo-linking> "View package in npm Registry")
`expo-linking` provides utilities for your app to interact with other installed apps using deep links. It also provides helper methods for constructing and parsing deep links into your app. This module is an extension of the React Native [Linking](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<https:/reactnative.dev/docs/linking.html>) module.
For a more comprehensive explanation of how to use `expo-linking`, refer to the [Linking into other apps](https://docs.expo.dev/versions/v50.0.0/sdk/linking/</linking/into-other-apps>).

## Methods[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<#methods>)
### `Linking.canOpenURL(url)`[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<#linkingcanopenurlurl>)
Parameter| Type| Description  
---|---|---  
url| `string`| The URL that you want to test can be opened.  
Determine whether or not an installed app can handle a given URL. On web this always returns `true` because there is no API for detecting what URLs can be opened.
Returns:
`Promise[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<https:/developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise>)<boolean>`
A `Promise` object that is fulfilled with `true` if the URL can be handled, otherwise it `false` if not.
The `Promise` will reject on Android if it was impossible to check if the URL can be opened, and on iOS if you didn't [add the specific scheme in the `LSApplicationQueriesSchemes` key inside Info.plist](https://docs.expo.dev/versions/v50.0.0/sdk/linking/</guides/linking#linking-from-your-app>).
### `Linking.collectManifestSchemes()`[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<#linkingcollectmanifestschemes>)
Collect a list of platform schemes from the manifest.
This method is based on the `Scheme` modules from `@expo/config-plugins` which are used for collecting the schemes before prebuilding a native app.
  * iOS: scheme -> ios.scheme -> ios.bundleIdentifier
  * Android: scheme -> android.scheme -> android.package


Returns:
`string[]`
### `Linking.createURL(path, namedParameters)`[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<#linkingcreateurlpath-namedparameters>)
Parameter| Type| Description  
---|---|---  
path| `string`| Addition path components to append to the base URL.  
namedParameters(optional)| `CreateURLOptions[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/</versions/latest/sdk/linking#createurloptions>)`| Additional options object.Default:`{}`  
Helper method for constructing a deep link into your app, given an optional path and set of query parameters. Creates a URI scheme with two slashes by default.
The scheme must be defined in the Expo config (`app.config.js` or `app.json`) under `expo.scheme` or `expo.{android,ios}.scheme`. Platform-specific schemes defined under `expo.{android,ios}.scheme` take precedence over universal schemes defined under `expo.scheme`.
#### Examples[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<#examples>)
  * Development and production builds: `<scheme>://path` - uses the optional `scheme` property if provided, and otherwise uses the first scheme defined by your Expo config
  * Web (dev): `https://localhost:19006/path`
  * Web (prod): `https://myapp.com/path`
  * Expo Go (dev): `exp://128.0.0.1:8081/--/path`


The behavior of this method in Expo Go for published updates is undefined and should not be relied upon. The created URL in this case is neither stable nor predictable during the lifetime of the app. If a stable URL is needed, for example in authorization callbacks, a build (or development build) of your application should be used and the scheme provided.
Returns:
`string`
A URL string which points to your app with the given deep link information.

### `Linking.openURL(url)`[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<#linkingopenurlurl>)
Parameter| Type| Description  
---|---|---  
url| `string`| A URL for the operating system to open, eg: `tel:5555555`, `exp://`.  
Attempt to open the given URL with an installed app. See the [Linking guide](https://docs.expo.dev/versions/v50.0.0/sdk/linking/</guides/linking>) for more information.
Returns:
`Promise[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<https:/developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise>)<true>`
A `Promise` that is fulfilled with `true` if the link is opened operating system automatically or the user confirms the prompt to open the link. The `Promise` rejects if there are no applications registered for the URL or the user cancels the dialog.

### `Linking.parseInitialURLAsync()`[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<#linkingparseinitialurlasync>)
Helper method which wraps React Native's `Linking.getInitialURL()` in `Linking.parse()`. Parses the deep link information out of the URL used to open the experience initially. If no link opened the app, all the fields will be `null`.
> On the web it parses the current window URL.
Returns:
`Promise[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<https:/developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise>)<ParsedURL[](https://docs.expo.dev/versions/v50.0.0/sdk/linking/<#parsedurl>)>`
A promise that resolves with `ParsedURL` object.
