# ![Expo DeviceMotion icon](https://docs.expo.dev/static/images/packages/expo-sensors.png)Expo DeviceMotion
[GitHub](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/<https:/github.com/expo/expo/tree/sdk-51/packages/expo-sensors> "View source code of expo-sensors on GitHub")[npm](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/<https:/www.npmjs.com/package/expo-sensors> "View package in npm Registry")
A library that provides access to a device's motion and orientation sensors.
[GitHub](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/<https:/github.com/expo/expo/tree/sdk-51/packages/expo-sensors> "View source code of expo-sensors on GitHub")[npm](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/<https:/www.npmjs.com/package/expo-sensors> "View package in npm Registry")
Android
iOS
Web
`DeviceMotion` from `expo-sensors` provides access to the device motion and orientation sensors. All data is presented in terms of three axes that run through a device. According to portrait orientation: X runs from left to right, Y from bottom to top and Z perpendicularly through the screen from back to front.
## Installation[](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/<#installation>)
Terminal
Copy
`- ``npx expo install expo-sensors`
If you are installing this in an [existing React Native app](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/</bare/overview>), start by [installing `expo`](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/</bare/installing-expo-modules>) in your project. Then, follow the [additional instructions](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/<https:/github.com/expo/expo/tree/main/packages/expo-sensors>) as mentioned by the library's README under "Installation in bare React Native projects" section.
## Configuration in app config[](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/<#configuration-in-app-config>)
You can configure `DeviceMotion` from `expo-sensor` using its built-in [config plugin](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/</config-plugins/introduction>) if you use config plugins in your project ([EAS Build](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/</build/introduction>) or `npx expo run:[android|ios]`). The plugin allows you to configure various properties that cannot be set at runtime and require building a new app binary to take effect.
### Example app.json with config plugin[](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/<#example-appjson-with-config-plugin>)
app.json
Copy
```
{
 "expo": {
  "plugins": [
   [
    "expo-sensors",
    {
     "motionPermission": "Allow $(PRODUCT_NAME) to access your device motion."
    }
   ]
  ]
 }
}

```

### `isAvailableAsync()`[](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/<#isavailableasync>)
> You should always check the sensor availability before attempting to use it.
Returns whether the accelerometer is enabled on the device.
On mobile web, you must first invoke `DeviceMotion.requestPermissionsAsync()` in a user interaction (i.e. touch event) before you can use this module. If the `status` is not equal to `granted` then you should inform the end user that they may have to open settings.
On web this starts a timer and waits to see if an event is fired. This should predict if the iOS device has the device orientation API disabled in Settings > Safari > Motion & Orientation Access. Some devices will also not fire if the site isn't hosted with HTTPS as `DeviceMotion` is now considered a secure API. There is no formal API for detecting the status of `DeviceMotion` so this API can sometimes be unreliable on web.
Returns:
`Promise[](https://docs.expo.dev/versions/v51.0.0/sdk/devicemotion/<https:/developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise>)<boolean>`
A promise that resolves to a `boolean` denoting the availability of device motion sensor.
